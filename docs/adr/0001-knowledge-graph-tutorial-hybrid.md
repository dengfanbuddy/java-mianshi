# ADR-0001：知识图谱 + 教程混合形态，主题级节点粒度

- 日期：2026-08-07
- 状态：已接受

## 背景

用户需要为 18 个分类补「教程/知识库」形态内容，用于知识欠缺时查漏补缺。候选形态：每分类一篇大教程 / 多篇独立小教程 / 知识图谱 + 教程混合。

## 决策

采用**知识图谱 + 教程混合**：每分类一张四层（入门→核心→进阶→实战）分层 DAG 图谱，节点=教程，边=前置依赖；节点粒度为**主题级**（每分类 8~12 篇，全站 16 个技术分类共约 150~200 篇）。

## 理由

- 分层 DAG 同时承担「知识体系可视化」与「学习路线图」两个职责，直接满足用户"循序渐进"的核心诉求。
- 主题级粒度（而非知识点级）使每篇教程 1~2 屏可读完，符合"补课"场景；与题库题目 tags 粒度对齐，错题→教程映射直接。
- 依赖未学完的节点灰显，形成视觉化的"下一步学什么"。

## 权衡

- 知识点级节点最详尽，但 30+ 节点/分类会使教程数量爆炸、图谱过载，第一版易烂尾。
- 模块级节点图谱简单，但每篇过长、知识点定位困难。
- 纯列表式路线最省成本，但失去依赖关系可视化，不达"图解"目标。

## 后果

- 每分类需先设计节点选题与依赖关系（制作阶段前置工作）。
- 图谱、教程数据、UI 三者耦合，后续改形态成本高（难逆转）。
