# 教程数据规范（window.TB）— 子代理生成教程时必须严格遵循

## 1. 文件与全局格式

- 每个分类一个文件：`data/tutorials/<分类id>.js`
- 全局对象：`window.TB`（Tutorial Bank），与题库 `window.QB` 平行
- 文件骨架：

```js
window.TB = window.TB || {};
window.TB["redis"] = {
  id: "redis",
  name: "Redis",
  icon: "🧠",
  nodes: [ /* 8 个教程节点 */ ]
};
```

- `icon` 沿用题库分类的 icon；`id`/`name` 必须与题库一致。

## 2. 节点（node）字段

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 全局唯一，`分类前缀-英文短横线`，如 `redis-data-structures` |
| title | string | 节点标题（图谱与目录显示） |
| layer | number | 0=入门 1=核心 2=进阶 3=实战 |
| depends | string[] | 前置节点 id 列表（必须是本分类内存在、且 layer 更小的节点） |
| covers | string[] | 关联题目 id 列表（必须从本分类题库 `questions[].id` 中真实选取，3~6 个） |
| quiz | string[] | 随堂小测题目 id（必须从本分类题库真实选取，恰好 3 个） |
| body | array | 正文块数组，见 §3 |

## 3. body 块类型（按序组合成八段结构）

每篇必须按顺序包含以下块，构成八段结构：

| 块 | 写法 | 对应段落 |
|---|---|---|
| lead | `{t:"lead", text:"..."}` | ①一句话定位 |
| pre | `{t:"pre", items:["...","..."]}` | ②前置知识 |
| h | `{t:"h", text:"..."}` | 小节标题（核心讲解内多级使用） |
| p | `{t:"p", text:"..."}` | 段落 |
| list | `{t:"list", items:["..."]}` | 无序列表 |
| code | `{t:"code", lang:"java", code:"..."}` | ④代码示例（Java 为主，贴合游戏服务器场景） |
| svg | `{t:"svg", svg:"<svg>...</svg>", caption:"图：..."}` | ⑤SVG 图解（每篇 1~3 个） |
| table | `{t:"table", head:["A","B"], rows:[["a","b"]]}` | 对比表格 |
| pits | `{t:"pits", items:["..."]}` | ⑥常见坑（每条=面试官爱挖的点） |
| callout | `{t:"callout", kind:"tip"|"warn"|"unverified", text:"..."}` | 提示框；⑦关联题目和⑧小结渲染时自动追加，不用写在 body |

> ⑦ 关联题目由 `covers` 驱动自动渲染；⑧ 小结用 body 末尾一个 `{t:"callout", kind:"tip", text:"小结：..."}` 表达。
> `text`/`code` 内可用 `\n` 换行；不要包含未转义的 `<`、`>`（如需展示泛型写 `List<String>` 直接写，HTML 渲染时统一转义——但 svg 块内的 svg 字段是原始 SVG，不转义）。

## 4. SVG 图解硬性规范（违反即返工）

1. `<svg viewBox="0 0 640 ...">`（宽固定 640，高自定），根 svg 不要写死 width/height 或写 `width="100%"` 即可（由 CSS 控制自适应）。
2. **颜色必须用 CSS 变量**，禁止写死色值（黑白文字除外）：
   - 文字/图标填充：`fill="var(--ink)"`
   - 次要文字：`fill="var(--muted)"`
   - 线条/边框：`stroke="var(--line)"`
   - 主强调色：`var(--accent)`、强调浅底 `var(--accent-soft)`
   - 难度绿/橙/红：`var(--lv1)`、`var(--lv2)`、`var(--lv3)`，浅底 `var(--lv1-bg)`/`var(--lv3-bg)`
   - 面板底色：`var(--panel)`；浅色块：`var(--bg)`
3. 所有中文标注字号 ≥ 12px；`font-family="inherit"` 或省略。
4. 不写 `<defs>` 渐变/滤镜（除非简单 `<linearGradient>` 两色）；不用外部字体、不用图片、不用 JS。
5. 标签必须完整闭合；`<text>` 内中文不要写 `&nbsp;`，直接空格。
6. 类型匹配：原理架构图（分层框图）、流程时序图（箭头+步骤）、对比图（并排框/表格形）、数据结构图（方框+指针箭头）。

## 5. 内容与质量要求

1. **准确**：涉及版本/参数/命令等事实点，先 `WebSearch` 验证（至少 3 个关键事实点），无法确认的加 `{t:"callout", kind:"unverified", text:"存疑：..."}`。
2. **完整**：一个主题讲透：是什么 → 为什么 → 怎么用 → 底层原理 → 游戏场景怎么落地 → 常见坑。
3. **循序渐进**：严格按 layer 0→3 的依赖顺序写作；先讲基础概念，再讲原理，最后实战。
4. **贴合用户背景**：邓凡是 10 年 Java 游戏服务器开发者（Netty/Disruptor/SpringBoot/Redis 集群/Kafka/分库分表/JUC/JVM，登录服/游戏服/支付服/日志服/GM 后台），代码示例尽量结合游戏服务器场景（排行榜、玩家档案缓存、在线列表、活动防重、技能 Buff、日志链路、GM 后台）。
5. **代码示例要能跑通**：JDK 8+ 语法，不用第三方库除非说明；关键代码附注释。
6. **每分类恰好 8 个节点**，覆盖该分类核心知识面；covers+quiz 合计的题目尽量覆盖全分类题目（总计约占该分类题目 60%+）。

## 6. 节点选题模板（以 Redis 为例的 8 节点）

layer0 入门：[数据结构总览] → layer1 核心：[持久化]、[淘汰策略与缓存三兄弟] → layer2 进阶：[主从复制]、[哨兵]、[Cluster 集群] → layer3 实战：[分布式锁与 Redisson]、[热Key/大Key治理与缓存一致性]。

> 每个分类的节点选题由子代理根据该分类题库实际内容自行拟定，但必须满足：8 个节点、四层分布合理（0/1/2/3 各约 1-2/2-3/2/1-2）、depends 依赖链真实反映"先学什么再学什么"。

## 7. 生成步骤（子代理必须执行）

1. 读题库 `data/<分类id>.js`，记录所有题目 id、tags、难度、考点分布。
2. `WebSearch` 验证至少 3 个关键事实点（版本特性/参数/命令），记录验证结果。
3. 拟定 8 个节点选题 + 依赖 + covers 映射。
4. 逐节点写 body（八段结构 + SVG）。
5. 用 `node` 跑一次结构校验（脚本见 tools/validate-tutorials.js 提示），或人工核对字段类型。
6. 输出文件到 `data/tutorials/<分类id>.js`，汇报：节点清单、验证过的事实点、covers 覆盖的题目数/比例。

## 8. 扩充模式（往现有分类追加节点，2026-08-07 新增）

用途：把某分类从 8 篇扩到 16 篇，**知识覆盖优先于题库关联**（用户明确要求"不一定要讲究面试题，知识越全越详细越好"）。

1. **不得重复已有节点主题**：先读现有 `data/tutorials/<id>.js`，新增节点必须覆盖现有 8 篇之外的领域。
2. **covers / quiz 允许空数组**：有天然对应的题库题就填真实 ID，没有就 `[]`。重心是知识点讲解而非做题。
3. **输出片段文件**（避免与正式文件冲突）：写入 `data/tutorials/parts/<分类id>-ext.js`，格式：
   ```js
   window.TB_EXT = [ /* 8 个节点对象，结构与 §2 完全一致 */ ];
   ```
   由主代理统一合并进正式文件。
4. **id 唯一**：新节点 id 前缀同分类，不得与现有 id 重复（如现有 `redis-data-structures`，新增用 `redis-advanced-structs`）。
5. **layer 与 depends**：新增节点可跨层，depends 建议指向"先学"的节点（仅推荐顺序，UI 已无锁定）。
6. **篇幅**：每篇正文尽量详尽（2000 字以上讲解 + 1~3 张 SVG），把该主题讲透：是什么 → 为什么 → 底层原理 → 怎么用 → 游戏场景落地 → 坑。
